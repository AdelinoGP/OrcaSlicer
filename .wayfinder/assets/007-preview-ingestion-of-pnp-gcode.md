# Preview ingestion of PNP G-code — verification & required annotation set

Sources: OrcaSlicer `GCodeProcessor.cpp/.hpp`, `ExtrusionEntity.cpp` (`string_to_role`), `Plater.cpp` (`load_gcode`), this checkout; pnp `crates/slicer-gcode/src/{emit,serialize,thumbnail}.rs`; a live `pnp_cli slice` run on `resources/regression_wedge.stl` (release binary, 2026-07-16). Ticket: [007](../tickets/007-preview-ingestion-of-pnp-gcode.md).

## Verdict

PNP G-code parses into a full `GCodeProcessorResult` **provided the fork forces the non-BBL tag table** (see Hazard). Feature coloring, layer detection, per-layer times, and filament volume all work today. Time estimates and filament stats are **computed by `GCodeProcessor` itself from the moves** — PNP's lack of stat comments does not blank the preview.

## Hazard — BBL tag table (fork-side fix REQUIRED)

`GCodeProcessor::s_IsBBLPrinter` is a static defaulting to **true**, set from the active preset vendor at `Plater::load_gcode` and re-derived inside `process_file` **only if** the file's config block has a non-empty `printer_model` (→ `starts_with("Bambu Lab")`). PNP emits **no `printer_model`**. If the flag is true, `reserved_tag` switches to the BBL table (`" FEATURE: "`, `" CHANGE_LAYER"`, `" LAYER_HEIGHT: "`); PNP's `;TYPE:`/`;LAYER_CHANGE` then match nothing → **preview collapses to one uncolored layer**.

Fork requirement: the `PnpSlicingProcess` result-ingestion path MUST set `GCodeProcessor::s_IsBBLPrinter = false` before `process_file` (v1 is Marlin-only, so no BBL printer is ever correct). Belt-and-braces pnp handoff item: emit `printer_model` in the CONFIG_BLOCK.

Related trap: `WipeTower.cpp`/`WipeTower2.cpp` constructors mutate the same static — irrelevant once native slicing is ripped out (ticket 008), but don't reintroduce.

## Absent annotations — all degrade gracefully

- **`; estimated printing time` / M73** — ignored on external load (`finalize(false)` skips post-process; M73 isn't a registered command). `GCodeProcessor` runs its own trapezoidal time estimator from moves + machine limits. PNP passes `gcode_flavor = marlin` (Marlin legacy → limits are read), but emits no `machine_max_*` keys → generic firmware defaults → time shown but approximate. **Consequence for ticket 011: preview/sidebar time estimates are NOT blank — they come from Orca's own simulation.**
- **`; filament used [mm/g]` lines** — ignored; volume computed per-move from `filament_diameter`. Grams/cost need `filament_density`/`filament_cost` in the CONFIG_BLOCK — PNP puts density only in the header (`; filament_density:` colon form, not parsed) → grams/cost fall back to defaults.
- **`;WIDTH:`** — optional; width computed from extruded volume per role, clamped. Fine.
- **`WIPE_START/END`, exclude-object, `COLOR_CHANGE`** — optional enhancements, not emitted, no breakage.
- **`printable_area`** — not emitted → default bed in the parsed result. In-GUI preview draws the plater's own bed, so cosmetic for v1; matters only for standalone drag-in of PNP files.

## Required annotation set (normative for the fork)

Must stay (any regression breaks preview): producer line containing `OrcaSlicer`; `;LAYER_CHANGE` per rendered layer with gap-free sequence; `;TYPE:` exact spellings from `string_to_role`; CONFIG_BLOCK ≥96 `; key = value` pairs including `gcode_flavor` and `filament_diameter`; HEADER/THUMBNAIL/CONFIG block ordering per pnp `docs/02_ir_schemas.md` envelope spec.

Fork-side: force `s_IsBBLPrinter = false` on the PNP ingestion path.

## New pnp handoff items (appended to the handoff doc)

10. **Viewer-config passthrough keys in CONFIG_BLOCK** — emit `printer_model` (non-Bambu), `filament_density`, `filament_cost`, `printable_area`, `nozzle_diameter`, and the `machine_max_acceleration_*` / `machine_max_speed_*` / `machine_max_jerk_*` family (from host raw_config passthrough or padding defaults). Effect: correct BBL-table derivation on drag-in, real grams/cost, sharper time estimates. Low effort — the serializer already writes arbitrary raw_config keys verbatim.
