# Fork OrcaSlicer frontend onto the PNP backend

## Destination

A handoff-ready design doc — optimized for subagent execution — for converting this OrcaSlicer checkout, in place, into a PNP-backed frontend: `pnp_cli` shell-out replaces `BackgroundSlicingProcess` slicing, native slicing (FFF `Print::process` and all SLA) removed cleanly, PNP's config system adopted with pass-through warnings for unresolved Orca preset keys, and PNP G-code rendered in Orca's preview. The map is done when every design decision needed to start implementation is resolved.

## Notes

- Domain: C++17/wxWidgets (OrcaSlicer, this repo) + Rust CLI backend (`F:\slicerProject\pinch_n_print`, binary `pnp_cli`).
- HITL tickets: use `/grilling` and `/domain-modeling`. Plan-only effort: tickets decide, they don't build.
- Tracker: local markdown. Tickets live in `.wayfinder/tickets/NNN-<slug>.md`; frontmatter `status/type/assignee/blocked-by` is authoritative. Claim = set `assignee`. Frontier = open, unassigned, all `blocked-by` closed.
- Standing facts:
  - GUI→slicing seam: `src/slic3r/GUI/BackgroundSlicingProcess.{hpp,cpp}` (state machine, worker thread, holds `Print*`/`SLAPrint*` + `GCodeProcessorResult*`), driven by `src/slic3r/GUI/Plater.cpp` via `background_process.apply(model, preset_bundle->full_config(...))` → `start()`. Results reach the GUI via wx events (`SlicingStatusEvent`, `SlicingProcessCompletedEvent`); preview consumes `GCodeProcessorResult` (`libslic3r/GCode/GCodeProcessor.hpp`) in `GUI_Preview`/`GLCanvas3D`. Multi-plate via `GUI::PartPlate`.
  - No existing subprocess/CLI slicing abstraction in OrcaSlicer — the seam must be newly built. `GCodeProcessor` can parse a G-code file: natural preview path.
  - PNP surface: `pnp_cli slice --model <stl/obj/3mf> --config <json> --output <gcode> --module-dir ... --thumbnail <png> --instrument-stderr` (JSONL progress, pnp `docs/09_progress_events.md`); `pnp_cli module config-schema` introspects config.
  - PNP-side gaps discovered here (e.g. missing Orca-compatible `;TYPE:` annotations) are recorded as precise **handoff items** for the pinch_n_print spec-packet workflow — not charted on this map.
  - Locked by grilling: shell-out integration (no FFI); v1 scope = slice + preview; PNP only (no native fallback); "Slice all" loops pnp_cli per plate sequentially; SLA removed entirely; Windows-first; long-lived product until pnp_studio (`F:\slicerProject\pinch_n_print_studio`, Bevy) matures — rip-outs must be clean and maintainable.
  - **PNP gaps are scheduled dependencies, not fixed constraints** (user, 2026-07-17): pnp-side features are implemented in parallel with this fork's roadmap, so each lands before the fork needs it. The fork therefore builds **no defensive UI** — no hiding, gating, or blocking — against a gap that will be closed before the feature is reachable here. Handoff items are prerequisites to schedule, not "either/or" (implement-or-hide) choices. Locked by ticket 012; it superseded ticket 004's non-uniform-scale block.
  - **The fork's v1 is silent about PNP gaps — no UI, no warning, no gate** (ticket 013, closing the loop 012 opened). 012 removed the restrictions and deferred all gap communication to 013; 013 made the warnings a log-only dev instrument. Net: nothing on screen ever tells a user a gap affected their slice. Any future ticket proposing user-facing gap UI is reopening both decisions, not filling a hole they left.

## Decisions so far

<!-- one line per closed ticket: [title](tickets/NNN-slug.md) — gist -->

- [PNP feature-coverage inventory](tickets/001-pnp-feature-coverage-inventory.md) — PNP covers the core single-material FFF slice surface with Orca-viewer-compatible G-code; hard gaps: no time estimates, no raft, Marlin-only flavor, unproven multi-material, GUI must render thumbnails, no multi-plate 3MF, non-uniform scale rejected. Full matrix + 8 pnp handoff items in [the inventory asset](assets/001-pnp-feature-coverage-inventory.md).
- [Upstream sync strategy](tickets/002-upstream-sync-strategy.md) — long-lived `pnp/main` branch off local `main`, fork point tagged `pnp-fork-base`; cherry-pick-only upstream sync (profiles/GUI/security fixes, no merges); this checkout loses canonical porting-source status — user keeps a separate pristine OrcaSlicer folder for pnp porting.
- [Preset→PNP config translation spec](tickets/005-preset-to-pnp-config-translation.md) — flat-key PNP JSON; of Orca's 925 keys, 65 map identically, ~30 via a verified rename/transform table, ~830 stay unsent with classified warnings; mechanism = one static table in a new `PnpConfigTranslator` GUI translation unit. Full four-tier table in [the mapping asset](assets/005-preset-to-pnp-config-mapping.md).
- [Model/geometry handoff format](tickets/004-model-geometry-handoff-format.md) — per-plate temp 3MF via existing `export_3mf(plate_idx)` (plate-local origin); sidecar per-object config and extruder assignments passed through raw with Orca keys (PNP-side parity is a handoff item); non-uniform scale ~~blocks slicing in GUI~~ (**superseded by ticket 012**: no check at all, PNP lifts the restriction first); multi-plate 3MF confirmed won't-fix.
- [Preview ingestion of PNP G-code](tickets/007-preview-ingestion-of-pnp-gcode.md) — verified: PNP G-code parses into a full `GCodeProcessorResult` (roles, layers, config block all match), with one fork-side MUST: force `GCodeProcessor::s_IsBBLPrinter = false` on the ingestion path (PNP emits no `printer_model`; the BBL tag table would collapse the preview). Time/filament stats are computed by Orca's own estimator from moves, so ticket 011's "absent estimates" premise is softened. Matrix + required annotation set in [the preview-ingestion asset](assets/007-preview-ingestion-of-pnp-gcode.md); new pnp handoff item 10 (viewer-config passthrough keys).
- [Progress, cancel, and error UX](tickets/006-progress-cancel-error-ux.md) — progress percent from JSONL events via GUI-estimated layer total (phase-weighted 0–10–90–100); degraded slices → one aggregated warning notification on completion; fatal errors show message+suggestion+stage with stderr tail in the log; slice-all keeps per-plate 0–100% with "plate N/M" text; orphan guard via Windows Job Object kill-on-close; no hang watchdog in v1; stream parse errors tolerated (exit code decides success). New pnp handoff items 11 (graceful cancel, from ticket 003) and 12 (layer_count in progress stream).
- [Native-slicing rip-out scope](tickets/008-native-slicing-rip-out-scope.md) — `Print::process()` has **four** production callers, not just BSP: Orca's headless `--slice` CLI (deleted — pnp_cli is the CLI), `CalibUtils`, and the profile-validator dev tool. Calibration UI survives as a **mock** (dialogs keep `Calib_Params` types; generators, `set_calib_params`, `Model::calib_pa_pattern` deleted; `Plater::calib_*` → "not implemented" stub). Slicing tests deleted, geometry/model/config tests kept. Support-painting's live preview (`generate_support_preview()` = real slice+supports) dropped → gizmo paint-only, new pnp handoff item 13. SLA: full cut incl. `ModelObject` SLA fields, `sla_shift_z` across 9 render files, and `init_sla_params()` — with **explicit SLA-project detection** in the 3MF importer, because `load_from_json` fails the *whole* project config on an unknown key (unlike the ini/gcode paths, which ignore per-key). `SLA/IndexedMesh` + `SLA/Rotfinder` survive (they back `AABBMesh` and the orient job). `GCodeProcessor` and variable-layer-height verified independent of slicing.
- [Slicing-seam replacement design](tickets/003-slicing-seam-replacement-design.md) — new `PnpSlicingProcess` replaces BSP wholesale but keeps its public surface (Plater ≈ type rename); `Print::apply()` retained for invalidation; one worker thread per slice; boost::process everywhere; v1 cancel = kill child (graceful cancel is a pnp handoff item); inputs in per-slice temp dir, output to `PartPlate::get_tmp_gcode_path()`; Plater's slice-all loop unchanged; reuse path keyed on plate validity + gcode file + `APPLY_STATUS_UNCHANGED`; failures → `SlicingError` via `exception_ptr`.
- [Thumbnails & G-code metadata gaps in the GUI](tickets/011-thumbnails-and-gcode-metadata.md) — two of three premises were false: Orca has **no sidebar stats panel** (`SlicedInfo` is orphaned `#if 0` dead code) and **no stats on the print-host upload path**. Real finding: 007's comment conflated two same-named structs — `GCodeProcessorResult::print_statistics` has volumes/times but **no weight or cost**; those live on `Print::m_print_statistics`, filled only by the `GCode.cpp` export path ticket 008 deletes, and `render_legend` reads them **unguarded** (`0.00 g`), unlike time (properly hidden at 0). Decided, all favouring a thin fork per ticket 002's merge cost: weight from pnp `slice_stats`, **cost computed fork-side** from Orca's preset (no cost field in pnp); thumbnails embedded *and* transcoded by an extended `pnp_cli` taking the size/format *list* (fork renders on the UI thread **before** spawn — deleting BSP's `thumbnail_cb`/`execute_ui_task` inversion — and ships PNG only; pnp stages PNG-passthrough first, covering 182/190 format-pinning profiles); **pnp emits M73 itself**, fork keeps `finalize(false)`. Load-bearing discovery: `process_file` **discards pre-applied config** for `EProducer::OrcaSlicer` (which pnp's header deliberately matches), so **handoff item 10 is mandatory, not nice-to-have**. New pnp handoff items 14 (thumbnail block is unparseable — missing Orca's inner `; thumbnail begin WxH len` tags — plus single-PNG CLI vs. Orca's 5-format list) and 15 (M73); item 2's field list amended. Full fork-dependency table in [the handoff asset](assets/handoff-pnp-gap-implementation.md).
- [v1 UI surface restrictions for PNP gaps](tickets/012-v1-ui-surface-restrictions.md) — **none: zero UI diff, no capability gate.** The premise inverted — since pnp gaps are scheduled to close before the fork needs them (see Notes), the fork builds no defensive UI. Raft: leave alone, already specced pnp-side (ADR-0009 + `raft-default-module.md`, both still proposed/sketch) — **corrects ticket 001's "❌ no raft"**, which probed the live schema and never checked the spec backlog; interim already covered by 005's `raft_layers`→`support_raft_layers` row. Flavor: leave alone, 005's `unsupported-feature` warning covers it for free — restricting presets would delete ~60% of the printer library (klipper 233 vs. marlin 92/marlin2 59), and Klipper eats Marlin G-code while `machine_start_gcode`/`machine_end_gcode` pass through untouched. Multi-material: leave alone, no warning (gap is unproven, not absent; the lever would have been `Sidebar::show_SEMM_buttons()`, not extruder count — AMS is 1 nozzle + N filaments). Non-uniform scale: **supersedes ticket 004** — no check at all. Consequence: ticket 013 now carries *all* gap communication, and Orca turns out to have **no capability system** (the choke point, unused, would have been `Tab::toggle_option`/`toggle_line` — `ConfigManipulation` is bypassed by the printer/filament tabs).
- [Config-warning UX for unresolved preset keys](tickets/013-config-warning-ux.md) — **no UI: warnings are a dev instrument, logged and never shown.** Premise inverted like 012's, so grouping/dedup/"don't show again" all dissolve. Accepted consequence: the fork's v1 has **zero gap-communication to the user** (a Klipper user gets Marlin G-code silently) — 012 deferred that signal here and here it is declined. Load-bearing discovery: `full_config()` returns all 925 keys with **defaults filled in**, so Tier-D keys are filtered against `FullPrintConfig::defaults()` via the existing `ConfigBase::diff()` (~830 records/slice → <20). That filter is **Tier-D-only** — Tier-B lossy fallbacks always record, because Orca's default `seam_position` is `spAligned`, the one value with no PNP equivalent, so a uniform filter would hide the table's most common fidelity loss on every default slice. Classes gain a fourth, `lossy-fallback` (sent, value substituted); no up-front classification pass (`not-yet-mapped` is the default); all four log. Sink = append-only `<data_dir>/pnp-config-warnings.jsonl` (not the temp dir 003 cleans) + one line in Orca's log; no rotation. Translator stays pure — returns `{json, warnings}`, `PnpSlicingProcess` writes. New pnp handoff item 16 (`aligned` seam mode, escalated to high priority — it hits every default slice).
- [pnp_cli distribution & discovery](tickets/009-pnp-cli-distribution-and-discovery.md) — pnp_cli.exe + modules/ ship flat next to orca-slicer.exe (drop of `cargo xtask dist` output); optional Preferences "PNP CLI directory" override wins when valid; module dir always `<exe dir>/modules`; handshake = startup `module config-schema` probe + per-slice JSONL `schema_version`, gating on semver major only (pnp wire-contract rule); failure → slicing disabled + persistent notification, GUI otherwise usable.
